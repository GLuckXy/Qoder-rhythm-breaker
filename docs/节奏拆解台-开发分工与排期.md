## 1. 前提与假设

| 假设 | 取值 | 若不成立 |
|---|---|---|
| 1 人日 | **有效 6.5 小时**（不含会议、试玩组织、上下文切换） | 若按 8h 名义工时算，供给虚高 23%，排期会假绿 |
| 原型可复用度 | 高：BeatClock / JudgeSystem / Spike / TrackMixer 雏形 / 双层画面结构 均可迁移（策划案附录 A） | 若需重写，+3 人日，方案直接不可行 → 必须开工前 30 分钟实跑原型确认 |
| 技术栈 | Phaser 3 + Vite + 原生 Web Audio；**不使用 Phaser sound manager** | 若团队不熟 Phaser → 降级纯 Canvas（R6），省 0.5 人日学习成本但粒子/补间自写 +1.5 人日 |
| 音乐 | 方案 C（全程序合成），noteEvents 同源驱动发声与障碍 | 若改 A/B，+2.5 人日且触发 P0-1 Safari OGG 问题 |
| 语言 | JS + JSDoc | 若上 TS，前 2 天各 +0.5 人日配置与类型，后期返工减少 |
| 无后端 | localStorage 存档 | 若加云存档，+2 人日，超出 9 天容量 |

**开工前必须已定稿的 PRD 事项**（否则 D1 无法结束）：P0-1 音乐方案、P0-2 物理参数表、P0-3 判定窗口基准、P0-4 noteEvents schema 归属、P0-5 复活/寂静段/分母口径；Q1–Q3。

## 2. 工作包划分

四个工作包，边界即 PRD 第 4 章的模块边界。**包与包之间只通过第 7 节的接口契约通信。**

### WP1 节拍与判定内核

范围：`BeatClock`（双时钟、段落、变速、预调度、pause/resume）、`JudgeSystem`（三档窗口、输入队列、空拍优先级、超时 MISS、校准偏移）、校准数据读写、存档 `Save.js`、场景 teardown 与 R 重开健壮性、**调试面板**。
交付物：可运行的节拍器 + 判定 + 漂移日志；debug 面板（漂移、窗口、待判定队列、事件流导出）。
**净 2.05 人日**（原型抵扣后）。
下游依赖：**所有包都依赖它**，D1 EOD 必须冻结 API。

### WP2 玩法实体与关卡运行时

范围：`Player`（自动奔跑 / 固定高度跳 / 冲刺 / 微调）、`Obstacle` 基类 + `Spike` / `Platform` / `Barrage`、`Timeline`（下层读谱 + 假标记渲染）、`LevelScene`（状态机、段落进入、寂静段、终点演出）、§7.5 物理参数落地与调参。
交付物：三类障碍各一关可通关；状态机日志与 PRD DIS-08 一致。
**净 5.0 人日**。

### WP3 音频与谱面内容

范围：`TrackMixer`（三声部 + 节拍器、gain 斜坡、静音/复活）、程序合成音序器（6 关音色预设）、`Sfx`（全套程序音效）、`PatternGenerator`（noteEvents → 障碍实例）+ **谱面自检脚本**（OBS-06、同拍不同类、核心节点数量下限）、6 份 `levelN.json` 的段落与 noteEvents 编写、编曲。
交付物：6 关音频 + 6 份全绿自检报告；一份 noteEvents 编写规范（供后续复用）。
**净 5.5 人日**（若升级自制 loop：+2.5）。

### WP4 表现、流程与发行

范围：上层世界渲染（地面线、视差电路、分区常量）、动效清单 7 项（PRD §15.2）、标题/选关/暂停/设置/结算五界面、第 1 关教学浮层、回放演出、视觉终校（粒子/bloom/配色）、兼容性与性能降级、Vercel + itch.io 部署与发行物料（README、60s 录屏、封面、中英文案）。
交付物：全流程无断点的可发布版本 + 发行物料包。
**净 6.75 人日**。

## 3. 人力方案

### 3.1 基线：2 人（推荐，与策划案一致）

**A · 客户端玩法工程师**（掌握 WP1 + WP2 + 部分 WP4）
关键词：时间、判定、实体、手感。
心智负担最重、返工代价最高的一路。**必须是团队里对「音频时钟」有手感的人。**

**B · 音频内容与表现工程师**（WP3 + 大部分 WP4）
关键词：声音、谱面、画面、流程、发行。
产出对外可见度最高（编曲、UI、录屏、README），也是 D9 的唯一责任人。

> 平衡说明：按「A = WP1+WP2、B = WP3+WP4」的直觉分法会得到 A 7.05 / **B 12.25**，B 直接超载 3.25 人日、A 闲 1.95 人日，第 4 天就会崩。所以下表把 WP4 里的**上层世界渲染、一半动效、兼容与性能**移给 A（这三项与 WP2 的时间纯函数公式同源，A 做反而更少沟通）。最终 A 9.55 / B 9.75。

### 3.2 降级：1 人

不可行按 9 天完成（19.3 人日需求 vs 9 供给）。两条路二选一：

- **工期拉到 13 天**（按 6.5h/日，19.3 人日 + 单人上下文切换损耗约 15% ≈ 13 天）。
- **仍守 9 天但砍到 9 人日范围**：6 关 → 保留但 L4 变速/L5 假节拍/L6 自由顺序全部降级为「同谱面换音色」；回放砍掉；校准小游戏砍掉；UI 只做标题+选关+结算（暂停用 ESC 直接冻结、设置内嵌选关）；视差与 bloom 砍到 1 层。这样能出「能玩、不完整」的作品集，但策划案 §1 的三条差异化卖点会剩 1.5 条。

**我的建议**：若真只有 1 人，选 13 天，不要选砍半。这个项目的所有卖点都在机制耦合上，砍机制等于砍产品。

### 3.3 升级：3 人

加 **C · 关卡内容与视觉工程师**，从 WP3 拿走「6 关谱面编写 + 自检」，从 WP4 拿走「动效清单 + 视觉终校 + 发行物料」。

| 角色 | 范围 | 人日 |
|---|---|---|
| A 引擎/判定/流程 | WP1 全部 + LevelScene/状态机/寂静段/存档 + 五界面 UI | 4.85 |
| B 玩法实体/音频运行时 | Player + 三障碍 + 物理调参 + Timeline + TrackMixer + Sfx | 5.5 |
| C 内容/表现/发行 | 音序器与 6 关编曲 + PatternGenerator 与谱面 + 上层世界 + 动效 + 视觉终校 + 回放 + 教学 + 部署物料 | 9.0 |

供给 27 vs 需求 19.3 → **富余约 7.7 人日**（C 稍紧、A/B 有余）。建议投向（按性价比排序）：① 音乐升级为自制 loop（+2.5，作品集听觉品质直接跳档）；② 试玩与调参轮次从 1 轮变 2 轮（+1）；③ 回放完整版（分轨重组 + 操作剪影，+0.75）；④ 选关徽章动画与视觉升级（+1）；⑤ 高对比/无障碍模式与导出码（+0.5）；⑥ 录屏剪辑与 itch 英文文案打磨（+0.5）。**不建议**加新机制或第 7 关。

## 4. 9 天双泳道排期（2 人基线）

> 每日 17:30 交验收证据（debug 截图 / GIF / 录屏）。**当日验收不过 → 当晚按 PRD §15.1 砍单，不挪用次日时间。**

### D1 · 节拍地基 —— 主线：契约冻结

| A（内核） | B（音频与内容） |
|---|---|
| BeatClock 迁移与补全：`now/beatAt/timeAtBeat`、段落表、`tempoChanges` 骨架、25ms 预调度队列、`pause/resume`（消 R11） | 仓库与工程化：Vite + ESLint + `base:'./'`、Vercel 预览环境、README 骨架、issue 模板 |
| JudgeSystem：三档窗口 + 缩放 + 下限保护（JDG-02）、输入队列匹配（JDG-03）、**空拍优先级（JDG-04）**、超时 MISS 由时钟回调（JDG-05） | `TrackMixer` 骨架：三轨 + 节拍器，`silence/revive` 走 0.1s 线性斜坡（MUS-01） |
| 调试面板：漂移、窗口、待判定队列、事件流导出（PERF-02/M-02） | 程序合成音色初版：kick / bass / synth 各一套 + 6 曲风参数预设（MUS-02） |
| **§7.5 物理与画面参数表定稿**（P0-2） | 与 A 共同定稿 **noteEvents schema**（P0-4），产出 `level1/2.json` 草案 |
| **验收线（A）**：开节拍器盲打按拍，Perfect 率 ≥ 90%，5 分钟漂移 ≤ 2ms，截图留证 | **验收线（B）**：三轨同时发声、各自 gain 可独立拉灭且无爆音（录音试听）；`level2.json` 能被 A 的面板正确解析 |

**D1 EOD 冻结点**：`BeatClock` / `JudgeSystem` / `DisassembleSystem` / `PatternGenerator` API + noteEvents 字段。此后改字段需走第 7 节流程。

### D2 · 角色与世界 —— 主线：时间纯函数打通

| A | B |
|---|---|
| `Player`：自动奔跑、**固定高度跳（滞空 = 0.9 × beat）**、冲刺、←/→ 微调、受击无敌帧 | `Timeline` 下层读谱：判定线 x=30%W、4 拍可见窗、流动标记、**声部形状编码（三角/横条/六边形，R12）** |
| `Obstacle` 基类（生命周期 + 时间纯函数定位）+ `Spike` 完整链路（从原型迁移并改造） | 上层世界：地面线 y=52%H、2 层视差电路、分区与配色常量文件（VIS-01/02/06） |
| 上层与下层共享 pxPerBeat（VIS-05），角色 x = 判定线 x | `PatternGenerator` v1：kick → spike；`selfTest` 首版（4 拍 ≤3、每 8 拍喘息、同拍不同类） |
| 对齐虚线动效 v0（TIM-03） | L1 谱面 + 编曲完成（临时正式鼓点） |
| **验收线（A）**：障碍掉帧 5 秒后仍落在正确拍位；跳跃时间与 `timeAtBeat` 一致 | **验收线（合）**：**第 1 关流程可玩**（用临时鼓点），能打出 PERFECT 并踩碎桩 |

### D3 · 声部系统 —— 主线：拆解闭环的情绪

| A | B |
|---|---|
| `DisassembleSystem`：hp、核心节点校验（DIS-02）、**复活选择规则（DIS-03，含并列/全满）**、状态机迁移与非法迁移报错 | `TrackMixer` 完整版：段落进入（`sections.layers`）、逐拍发声由 noteEvents 驱动（**MUS-03 同源**）、节拍器轨 |
| 拆解演出 v1：在场障碍全屏碎裂 + 降饱和 0.3s + 大字标题 + gain 淡出**同帧触发**（DIS-04） | `Sfx` 全套程序音效：PERFECT/GOOD/MISS/碎裂/复活/UI/变速提示/终点踩灭（MUS-04） |
| 复活演出与「不补发历史障碍」（DIS-05） | L2 编曲 + 谱面；音量三通道与持久化（MUS-05） |
| **D3 决策执行**：确认音乐方案 C 收口（不做任何音频文件依赖，P0-1） | 混音：三轨相对响度、拆解后「安静感」是否成立（自己盲听对比） |
| **验收线（合）**：**踩碎 4 桩 → 鼓消失 → 世界变安静，情绪到位。** B 录 15 秒 GIF，两人一起看一遍再判定 | |

## 8. 分支、集成与每日节奏

### 8.1 分支策略（对策划案 §11.4 的修改建议）

策划案「每关一个分支 + D7 起只 cherry-pick bugfix」对 2 人团队过重：六条分支 × 共享 `LevelScene.js` = 每天都在解决同一处冲突。

**建议改为**：
- `main` 唯一长期分支，每日 17:30 前各自 `merge` 或 PR 到 main（小步、当日集成）。
- 只在**内容**上开分支：`content/l4-tempo`、`content/l5-glitch`、`content/l6-freeorder`（这些主要是 JSON + 少量机制代码）。
- 里程碑 tag：`m1-kernel`（D1）、`m2-six-levels`（D5）、`m3-flow-complete`（D6）、`m4-polish-locked`（D8）、`v1.0.0`（D9）。
- D7 起：main 只收 bugfix；数值调整只改 `src/data/`；任何「想加个效果」的冲动进 `backlog.md`，不进 main。

### 8.2 代码规范（3 条硬性）

1. 判定/调度/障碍定位路径**禁止**出现 `scene.time`、`this.time.now`、`performance.now()`、`Date.now()`（Code review 打回项，支柱 1）。
2. 一切颜色/字号/分区/物理常量从 `theme.js` / `physics.js` 取，禁止散落字面量。
3. 场景 teardown 集中一处（`LevelScene.shutdown()` 里显式清 interval、音源、事件监听、对象池），新增定时器必须在 shutdown 登记 —— 这是 R 重开 bug 的根因防线（PERF-08/T12）。

### 8.3 每日节奏

```
09:30  15 分钟站会：昨日验收线过没过 / 今日目标 / 阻塞 / 是否需要改契约
12:00  契约检查点（D1/D2/D3/D6 有定稿事项）
14:00  集成窗口 1：各自 merge 到 main，跑一次全量自检
16:30  集成窗口 2：合并 + 联调（只跑「对方需要我方什么」那一条）
17:30  交验收证据（截图/GIF/录屏/日志），写「今日达成 / 明日首件事」到 devlog.md
18:00  若验收不过 → 执行砍单流程（第 12 节），不加班补次日内容
```

**为什么需要两个集成窗口**：本项目 80% 代码在 `LevelScene.js`，一天两次集成能把冲突控制在 10 分钟内。攒到晚上合一次是这类项目的头号时间黑洞。

| A → B | 判定事件流 JSON 导出按钮（§8.4） | D1 | B 用来验证「听到的」与「判定到的」一致 |
| B → A | `levelN.json` + noteEvents（含 `core` 标记） | D2 起逐日 | A 的障碍生成唯一输入 |
| B → A | `checkLevel.mjs` 自检报告（每关密度/同拍/核心数） | D4 | A 无需读谱面细节即可确认设计约束成立 |
| B → A | 三音色试听音频（或直接在页面里播） | D2 | A 的跳跃滞空时长必须与可听到的 beat 匹配 |
| A → B | `physics.js` 常量 + 跳跃包络可视化开关 | D2 | B 排版障碍时有硬边界，不会排出跳不到的平台 |
| A → 所有人 | 每次提交前的 `contractTest.mjs` | D2 起 | 防变速/事件流/密度回归 |
| B → 所有人 | 试玩记录表模板（3 人 × 每关：卡点、首句提问、重玩与否、deltaMs 分布） | D5 | D7 验收线与 P0-3 调参依据 |
| 双方 | `backlog.md`（想加的效果一律先写不实现） | D1 起 | 防 D7/D8 范围漂移 |

**联调三条铁律**

1. **任何「手感不对」的问题，先用数据定位归属**：导出事件流看 `deltaMs`。若 \|delta\| 稳定偏正 → 校准问题（A）；若偏散 → 预告/读谱问题（B）；若集中在某类障碍 → 谱面问题（B）；若集中在变速附近 → 时钟问题（A）。禁止两个人同时改代码「试一下」。
2. **改配置不改代码**（LVL-03）。所有平衡调整走 `src/data/`，两人可在同一文件不同关的行上并行。
3. **不在对方 domain 里调试**。A 不用 B 的编曲来判断 A 的判定精度，用节拍器轨。
