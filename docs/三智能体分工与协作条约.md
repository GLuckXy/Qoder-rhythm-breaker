## 1. 先承认 agent 与人不一样：5 条差异决定条约形状

| 差异 | 人类团队 | 三 agent 团队 | 对本项目的直接后果 |
|---|---|---|---|
| 记忆 | 有连续上下文，咖啡时间同步 | **会话结束即丢失**，只有文件留着 | 交接必须写文件；STATE.md 不写就等于该项目失忆 |
| 并行成本 | 沟通贵，并行省时间 | 并行几乎免费，但**同文件写冲突致命** | 切分依据不是技能，是「写入文件集合不相交」 |
| 感知 | 能听、能看、能觉得爽 | **听不见也看不见**，除非有断言 | 一切主观项必须先降级为可断言的结构，或交人类 |
| 完成判定 | 会自我怀疑 | **会自信地声称完成**（假完成是头号风险） | 没有 verify 命令的卡不许开工；DoD 必须贴输出 |
| 范围控制 | 会权衡工期 | 会「顺手优化」并引入新依赖 | 每卡锁 scope；禁止 npm 安装；砍单只能人批 |

由此得出三 agent 的切分三原则：

1. **按决策域切，不按工作量切**（工作量对 agent 不是硬约束，一致性才是）。
2. **文件所有权必须两两不相交**——尤其 `LevelScene.js`，它原本 80% 代码量，是全项目最大冲突源。解法见 T3：**把它降成 ≤250 行的薄编排层**，逻辑全部下沉到 systems/objects/effects。这是三 agent 能并行的前提条件，不是优化项。
3. **每个 agent 的产出必须自带机器可读的验证信号**，否则它无法自我纠错，只会反复交回不可用的东西。

## 2. 三个智能体

| ID | 名称 | 一句话使命 | 独占域 | 卡片数 | 净负载 |
|---|---|---|---|---|---|
| **CORE** | 时序与流程内核 | 让「拍」成为全项目唯一真相，并让玩家从点开页面走到第 6 关结算 | 时钟 / 判定 / 拆解规则 / 状态机 / 存档 / 界面流程 / 构建发布 | 20 | 6.85 人日当量 |
| **WORLD** | 世界与表现 | 把拍变成看得见、能跳、能撞、能拆的上下两层画面 | 玩家 / 三类障碍 / 时间轴 / 视差 / 演出动效 / 视觉规范 | 17 | 6.75 |
| **SOUND** | 声音与谱面内容 | 让 noteEvents 同时成为「听到的歌」与「打的东西」，并产满 6 关 | 音序器 / 三轨混音 / SFX / 6 份关卡 JSON / 谱面自检 | 21 | 5.70 |

三个 agent 的名字就是它的**否决权范围**（见 §5 T20 仲裁表）：CORE 说「这个时刻不对」，WORLD 说「这个画面读不出来」，SOUND 说「这个谱面不可玩」。

### 2.1 CORE · 时序与流程内核

**要做什么（按重要性）**

1. `BeatClock`：`now()` = `AudioContext.currentTime`；`timeAtBeat/beatAt` 支持段落变速的分段积分；25ms 预调度循环；`pause/resume` 内部重算时间原点（不重置拍序）。
2. `JudgeSystem`：三档窗口 + 关卡缩放 + 下限保护；「最近未判定障碍」匹配；**空拍 vs 落地预输入优先级**（PRD JDG-04）；超时 MISS 由时钟回调驱动；输出 §8.4 事件流。
3. `DisassembleSystem`：hp 增减、**复活选择规则**（并列 kick>bass>synth、全满不改音频）、`DISASSEMBLED→PEAK` 回退的世界重建指令、寂静段与终点推进。
4. 薄 `LevelScene`：只做事件接线与生命周期；`shutdown()` 显式登记并清理所有 interval/音源/监听（这是 R 重开 bug 的总闸）。
5. `physics.js` + `save.js` + `config.js`（窗口基准）+ `DebugPanel` + `contractTest.mjs` + `MockClock`（供另两个 agent 离线开发）。
6. 全部界面与流程：标题 / 选关 / 暂停 / 设置 / 结算 / 校准 / HUD 数据侧 / 教学浮层触发 / AudioContext 手势 resume。
7. 工程与发行：`vite.config`、构建产物 base 路径、四浏览器实测、Vercel 集成、README 技术章节、**main 的唯一写权限**。

**它的成功标准**：`npm run check:contract` 全绿；第 4 关跨变速点误差 < 1ms；R 连打 20 次节点数回基线；从标题到 L6 结算零断点；把链接发出去有人能玩。

### 2.2 WORLD · 世界与表现

**要做什么**

1. `Obstacle` 基类 + `Spike`/`Platform`/`Barrage`：位置一律 `x = judgeX + (t_obstacle - now) × pxPerSec`，**禁止速度积分**；核心节点视觉辨识（描边/高亮，非核心不涨 hp 的视觉表达）。
2. `Player`：自动奔跑、固定高度跳（滞空 = 0.9 × beat）、冲刺（0.35 拍位移 + 无敌）、←/→ 微调、落地微尘/跳跃拖尾/奔跑挤压。
3. `Timeline`：下层判定线 x=30%W、4 拍可见窗、标记右→左流动、变速时**按拍等距**、三声部形状编码（三角/横条/六边形）、假节拍错误标记（只污染这一层）、对齐虚线。
4. `EffectSystem`：边缘脉冲、PERFECT 22 粒 + 2 帧顿帧 + 金闪、拆解碎裂 + 降饱和 0.3s + 大字、MISS 红 vignette + 14px 衰减震屏、粒子/bloom 上限与降级顺序（先粒子后 bloom）。
5. `theme.js`（色板/字号/分区常量，全项目唯一取色入口）+ 上层世界（地面线 y=52%H、2 层视差电路、分关色温差异）。
6. `screenshotCheck.mjs` + 页面内 `?selftest=render` 端点（导出判定线 x、障碍位置换算差、分区比例、灰度可辨性等 JSON）。
7. 性能侧：第 6 关高密度段帧时间曲线、掉帧时的降级开关实现；回放舞台的角色剪影渲染（分轨重组归 SOUND）。

**它的成功标准**：截图灰度化后仍能分辨三声部；上层与下层判定线在任何帧落在同一 x；不看时间轴试玩能通关；1080p 稳定 60fps。

### 2.3 SOUND · 声音与谱面内容

**要做什么**

1. `TrackMixer`：三声部 + 节拍器轨，每轨独立 gain，`silence/revive` 走 0.1/0.15s 线性斜坡（**禁止瞬时切换**，防爆音）；段落进入由 `sections.layers` 驱动。
2. `SynthVoices`：6 曲风参数预设（极简电子/Synthwave/Chiptune/DnB/Glitch/完整编曲），全程序合成，**零音频素材文件**（这条同时消掉 Safari OGG 阻断）。
3. `Sfx`：PERFECT/GOOD/MISS/碎裂/复活/UI/变速提示/终点踩灭，全程序合成。
4. `PatternGenerator`：`noteEvents` → `ObstacleInstance[]`（纯函数，含 `core`/`pitchTier`/`speed`）；`checkLevel.mjs`：4 拍 ≤3、每 8 拍喘息、同拍不跨类、核心节点 ≥12、时长落在 60–90s。
5. **6 份 `levelN.json` 全部谱面与编曲**（D5 全部写完，这是本项目内容侧唯一交付）。
6. `audioAssert.mjs`：把可断言的部分做成纯结构断言（事件时刻、gain 包络采样、轨间响度、loop 与拍边界对齐）；浏览器端 `?selftest=audio` 导出 JSON 供自检。
7. 回放的分轨重组（按事件流 `hp` 顺序重建编曲，2× 加速版为默认）；音量三通道。

**它的成功标准**：`check:level --all` 六份全绿；`check:audio` 无爆音（斜率断言）且轨间响度差 ≤ 3dB；关掉画面纯靠耳朵能按拍预判每一件事；6 关听感有区分度。

### 2.4 边界（谁都不许越的三条线）

- 判定与时刻 = CORE 独占。WORLD 不得在自己文件里算「这个障碍该不该被打到」，只消费 `Judgment` 事件。
- 渲染与可读性 = WORLD 独占。CORE 不得为了省事在 LevelScene 里画东西。
- 谱面数据 = SOUND 独占。CORE/WORLD 不得往 `levelN.json` 里塞调试用的临时事件、不得在代码里硬编码 pattern（T1）。

## 3. 轮次排期（D1–D9 验收门不变，三线并行）

## 4. 协作条约（T1–T26，逐条都有判定方法）

**任何一条被违反，集成窗口直接退回该 agent，CORE 不代改。** 这是条约能被执行的前提。

### A 组 · 真相与所有权

**T1 谱面唯一真相。** `noteEvents` 是节拍序列的唯一来源：发声、障碍、自检三处都从它生成。任何代码里出现 >8 元素的时序字面量数组即为违规。
*判定*：`grep -RnE "\[[0-9., ]{24,}\]" src/` 白名单外命中 → 退回。

**T2 一个文件只有一个 Owner。** 所有权表见各 agent 职责卡与 [CONTRACTS.md](CONTRACTS.md)。非 Owner 需要改 → 提 CR 卡（模板在 CONTRACTS.md 末尾），由 Owner 实施。
*判定*：每卡的 `writes` 字段与 git diff 路径比对；出现他域路径 → 退回。

**T3 `LevelScene.js` 必须是薄编排层 ≤250 行。** 所有玩法逻辑下沉到 `systems/` `objects/` `audio/`。这条是三 agent 能并行的结构性前提。
*判定*：`wc -l src/game/scenes/LevelScene.js`。

**T4 时间真相唯一。** 判定/调度/定位路径禁止 `scene.time`、`this.time.now`、`performance.now()`、`Date.now()`。用 ESLint `no-restricted-globals` + 一条 grep 门禁实现，不靠自觉。
*判定*：`npm run lint` + `check:contract`。

**T5 冻结契约只加不改。** D1 EOD 冻结的 5 个契约（BeatClock / Judgment / ObstacleInstance / noteEvents / 事件流）语义不可变；新增字段可，改语义需三方各出 1 张回归卡 + 人类确认。

**T6 Mock 优先，禁止空等。** CORE 在 D1 交付 `MockClock`（可注入虚拟时间与节拍序列）与 Mixer/Sfx stub。WORLD/SOUND 一律对 stub 开发，不得因「内核还没好」而停工或自行造轮子。
*判定*：任何一卡的 `verify` 能在不启动真实音频的情况下通过。

### B 组 · 并行与集成

**T7 写入集合两两不相交。** 每轮开工前三个 agent 先在 STATE.md 声明本轮 `writes`；若相交，由人类或编排者拆成不同轮次，不许两个 agent 写同一个文件。
*判定*：STATE.md 三个 `writes` 列表求交集为空。

**T8 只 import 契约，不读实现。** WORLD/SOUND 只使用 CONTRACTS.md 列出的 API 签名；不得为了「看看怎么实现」深入他人模块（既浪费上下文，又诱发越界改动）。

**T9 小步频繁。** 单卡 ≤600 行 diff、≤1 个主题；同一轮内两个集成窗口（14:00 / 16:30）。攒到晚上合一次在 agent 协作里更危险，因为两个 agent 都不知道对方做了什么。

**T10 单写者集成。** 只有 CORE 有 `main` 写权限；WORLD/SOUND 推 `agent/world`、`agent/sound`。CORE 在集成窗口只做三件事：合并、跑 `verify:all`、把失败连输出打成缺陷卡退回。**CORE 不得代改他人代码**（否则它会变成全局瓶颈且吞掉别人的错误）。

**T11 每轮打 tag。** `r1-contract`、`r2-level1`、…、`r6-flow`。任何一轮崩了就 `git reset` 到最近绿 tag 重来，不在坏状态上继续盖。

### C 组 · 验证与完成定义

**T12 无 verify 不许开工。** 每张卡的 `verify` 字段必须是可执行命令（或"打开 `?selftest=xxx` 读 JSON 并比对"）。纯主观的卡必须显式标 `🚩human`，不许伪装成可自动验证。

**T13 DoD = verify 通过 + `npm run build` 通过 + `console` 零报错，且必须贴出实际输出。** 未运行就声称完成 = 本次协作最严重的违规，一次即上报人类，不等累计。

**T14 不许让测试变绿，要让代码变对。** 禁止修改、注释、跳过他人或自己的 verify 与断言。测试红且确实是被卡住的合法变更 → 提 CR 卡说明理由，由 Owner 改测试。

**T15 主观项先转结构断言。** 音频 → 纯函数导出事件时刻与 gain 包络采样 + OfflineAudioContext 峰值/斜率/轨间响度；画面 → 截图 + 像素与几何断言（判定线 x、分区比例、灰度可辨性、帧时间）；手感 → 事件流 `deltaMs` 分布。**能断言的全部归 agent，不能断言的送审美门。**

**T16 审美不许独断。** 涉及音色、配色、演出强度、关卡难度的判断，agent 交 **2–3 个候选 + 各自一句理由**，由人类在审美门挑选后写进 STATE.md 的 Decisions。选定之前不许写死进代码路径（可放 `theme.js`/`voices.js` 的 preset 里待选）。

### D 组 · 上下文与会话

**T17 每轮开头读，每轮结尾写 STATE.md。** 结构：`本轮变更 / 当前可运行状态 / 已知红点 / 下一轮第一步 / Decisions`。不写完不许结束会话——agent 没有记忆，STATE.md 就是这个项目的记忆。

**T18 改动陌生文件前先自证 5 行。** 任何 agent 要改一个它没写过的文件，先在 STATE.md 写「这个文件做什么 / 我为什么必须改 / 改完怎么验证」，再动手。这条专治幻觉式改动。

**T19 禁止新增依赖。** 允许清单：`phaser`、`vite` 及其官方插件、`eslint`。需要别的（含任何音频工具库、UI 框架、测试框架）→ 先开一张 `dep-*` 卡并说明收益，人类批准后才装。**agent 特别容易顺手 `npm i`，而这会静默摧毁 T13 的可复现性。**

### E 组 · 决策与仲裁

**T20 否决权按域分配。**

| 争议 | 拍板 | 需咨询 |
|---|---|---|
| 时刻/窗口/复活规则/状态机/存档/界面流程 | **CORE** | SOUND（音频反馈） |
| 判定线位置/滚动速率/障碍几何/动效强度/配色/性能降级 | **WORLD** | CORE（pxPerSec 与 beat 换算） |
| 谱面数据/密度/音色/轨间响度/喘息分布 | **SOUND** | WORLD（可读性）、CORE（约束可行性） |
| 跨域（例：平台三档高度可达性） | 三人各自出一句结论，冲突 → T21 | |
| 砍单、上线时间、发布 | **仅人类** | 三 agent 只能提建议卡 |

**T21 跨域冲突 15 分钟未达成 → 不空转。** 写进 `CONFLICTS.md`，临时采用**最保守方案**（对玩家最不易出错的），继续推进，提交人类仲裁。禁止用「先按我的做，回头再统一」。

**T22 手感归因协议（避免三个 agent 同时改同一症状）。** 「判定不准」先用事件流定位归属：`|delta|` 稳定偏正 → CORE（校准）；偏散 → WORLD（读谱/预告）；集中在某类障碍 → SOUND（谱面）；集中在变速附近 → CORE（时钟）。**归因没做之前，两个 agent 同时改代码「试一下」= 条约违规。**

**T23 决策留痕一行一条。** 写入 STATE.md Decisions：`D4-CORE 窗口基准定为 ±60/±110，理由：浏览器输出延迟实测 40-90ms`。

### F 组 · 范围与缺陷

**T24 只完成卡的 scope。** 顺手发现的改进写 `backlog.md`，不写代码。范围蔓延对 agent 的杀伤大于对人：人会觉得"快做完了"而刹住，agent 不会。

**T25 缺陷卡格式固定。** 现象 / 复现步骤 / 期望 / 实际 / 涉及卡号 / verify 输出。CORE 退回缺陷时必须附完整命令输出，禁止「跑不过」三字。

**T26 阻断定义。** 白屏 / 无法通关 / console 报错 / 判定完全失准 / 60fps 不达标 = 阻断，当日修（CORE 判定是否阻断）；其余进 backlog。D7 起 main 只收 bugfix。

## 5. 三个 agent 共用的测量回路（没有它，条约只是纸）

| 工具 | Owner | 消费者 | 输出 | 服务于 |
|---|---|---|---|---|
| `MockClock` + stub（Mixer/Sfx/ObstacleFactory） | CORE | WORLD、SOUND | 可注入虚拟时间的时钟，无浏览器可跑 | T6 |
| `DebugPanel`（`D` 键）：当前拍、`now()`、待判定队列、窗口实际值、`driftMs` | CORE | 全员 | 屏幕叠加 + 一键导出事件流 JSON | T15、T22 |
| `npm run check:contract` | CORE | 全员（提交前） | 变速换算/事件流/typedef 字段回归 | T4、T5 |
| `npm run check:level -- --all` | SOUND | WORLD、CORE | 每关：密度、同拍跨类、核心数、时长、喘息表 | T1、T15 |
| `npm run check:audio` | SOUND | CORE、人类 | 事件时刻表、gain 包络采样、爆音斜率、轨间响度 | T15 |
| `npm run check:render` | WORLD | CORE、人类 | 截图 + 几何断言（判定线 x 上下层一致、分区比、灰度可辨） | T15 |
| `npm run verify:all` | CORE | 集成窗口 | 上述四项 + `vite build` | T13、T10 |
| 页面内 `?selftest=render` / `?selftest=audio` | WORLD / SOUND | 各自 + 浏览器自动化 | JSON（供 agent 读取，agent 无法"看/听"的替代通道） | T15 |

**关键实现约定**：所有可断言逻辑写成**纯函数**（输入配置/时间 → 输出结构），浏览器只负责执行。这样 agent 在 Node 里就能验证大部分东西；剩下必须进浏览器的部分，用页面内 selftest 端点导出 JSON（若当前环境有浏览器自动化则直接驱动，否则由人类打开一次贴回结果）。

## 7. 编排者协议（谁派发轮次）

需要一个「编排者」角色（人类，或一个不写业务代码的协调 agent），职责只有 5 件：

1. 每轮开工：读 STATE.md → 按 §3 给三个 agent 各派 ≤3 张卡 → 校验三方 `writes` 无交集（T7）。
2. 集成窗口：触发 CORE 合并与 `verify:all`（T10）。
3. 主持 3 个审美门与 2 个决策点（D3 / D5 / D7 / D8），并只在这些地方给判断。
4. 执行砍单与发布（T20 末行：agent 无此权限）。
5. 冲突升级：T21 的 15 分钟计时与仲裁。

编排者**不写代码、不评审实现细节**，否则它会被拖成第三个 agent，而项目失去唯一的记忆写入者。

### 7.1 派发一条卡时的固定五要素

```
卡号 K-07 | 领 agent CORE | 依赖 K-02,K-01 | writes: src/game/systems/DisassembleSystem.js
reads: CONTRACTS.md#judgment, STATE.md
verify: node tools/contractTest.mjs --case revive-tie  →  期望 kick>bass>synth，输出 PASS
```

缺任一要素的卡不许派发（T12 的源头执行）。

## 8. 与原策划案的差异说明（保留的 / 改掉的）

**保留不变**：全部设计支柱、9 天节奏与每日验收门内容、砍单优先级、6 关规格、双时钟架构、配置表驱动、方案 C 音乐、DoD。
**改掉**：

2. 「每关一个分支」→ 单 main + 每轮 tag + `agent/*` 短分支（人版本 §8.1 已建议，agent 版本更必要：三条分支 × 三个 agent = 集成地狱）。
