## 1. 产品定义

### 1.1 一句话

逆向节奏游戏：玩家不跟随音乐，而是**拆解音乐**。每个声部（鼓 / 贝斯 / 合成器）是一类世界机关，踩拍 PERFECT 累积到 4 次即把该声部从编曲和关卡中同时抹掉；通关后只剩节拍器，最后一拍踩灭它。

### 1.2 硬约束（继承策划案）

| 项 | 规格 |
|---|---|
| 类型 | 2D 节奏动作 + 自动奔跑平台跳跃 |
| 平台 | PC 浏览器（键鼠为主），响应式兼容平板触控 |
| 技术栈 | Phaser 3（渲染/场景/补间/镜头）+ Vite + 原生 Web Audio API（**不使用 Phaser sound manager**） |
| 单局 | 60–90 秒 / 关 |
| 内容量 | 6 关，总流程 15–20 分钟 |
| 存档 | localStorage |
| 发行 | Vercel + itch.io |
| 语言 | 中文 UI（itch.io 页面文案另出英文版，属发行物不属游戏内） |
| 素材 | 零手绘素材：几何图形 + Canvas 渐变 + 粒子 + bloom；图形全程序绘制；字体走系统栈 |

### 1.3 目标用户与体验承诺

核心用户：玩过 osu!/Cytus/DJMAX 一类音游、能在 60 秒内理解「操作改变音乐」这一钩子的玩家；以及看作品集的技术面试官。

三条必须兑现的体验承诺（可试玩验证）：

1. **越玩越薄**：拆解瞬间，玩家能同时「听到少了一层」「看到该类障碍消失」「看到画面降饱和脉冲」——三者必须同一帧发生。
2. **双读谱殊途同归**：只看下层时间轴能通关；只看上层世界也能通关（D7 验收线）。
3. **失误不终止但改变音乐**：MISS 后耳朵立刻能听出「歌变吵了」。

### 1.4 成功度量

| 维度 | 目标 |
|---|---|
| 完赛 | 6 关全部可通关并正确结算 |
| 手感 | 未接触玩家 3 人中，0 人询问「怎么操作」，≥1 人主动重玩 |
| 精度 | 连续运行 5 分钟判定漂移 ≤ 2ms（自测日志） |
| 性能 | 1080p / Chrome 稳定 60fps，console 零报错 |
| 传播 | 可直接点开链接玩，无需任何指导；有 60 秒实机录屏 + README |

## 2. 设计支柱 → 可验证约束

设计支柱如果不落到「谁违反它就是 bug」，就只是口号。逐条翻译如下。

| 支柱 | 落地约束（代码/评审规则） | 违反判定 |
|---|---|---|
| 听觉即真相 | 判定 100% 由音频时钟驱动，**任何**判定/调度/障碍位置计算禁止读 `scene.time`、`performance.now()`、`Date.now()`；第 5 关假节拍只污染下层时间轴渲染，禁止污染音频与上层世界 | Code review 中出现 `this.time.` 于判定路径 = 打回 |
| 操作极简 | 全局只有 4 个功能性输入：跳（J/Space）、冲（K）、微调（←/→）、系统（R/Esc）。禁止新增任何需要组合键、长按蓄力、连打的操作 | 新增键位 = 需求变更，需制作人签字 |
| 失误有代价但不终止 | 不存在 HP、不存在死亡、不存在中途 Game Over；MISS 后果只允许是「连击清零 + 声部复活 + 0.5s 无敌帧」三件套 | 出现「失败/重试」弹窗 = bug |
| 60 秒一循环 | 单关 `lengthBeats / BPM × 60` 必须落在 60–90s；重开成本 ≤ 1.5s（含场景重建） | 单局 > 95s 或重开 > 2.5s = 阻断 bug |

## 3. 术语与口径

| 术语 | 定义 | 口径注意 |
|---|---|---|
| 拍 (beat) | 以关卡 BPM 定义的时间单位；`beat = 60/bpm` | 变速关内「第 N 拍」指**累计拍序**，不是等长时间 |
| 判定线 | 下层时间轴上玩家输入对应的读谱位置，`x = 30% W` | 上层世界的判定发生位置见 §7.5（建议与下层同 x） |
| 声部 (track) | kick / bass / synth 三条逻辑音轨，各绑一类障碍与一种颜色 | `hp` 与「是否静音」是两个独立状态，不要混用 |
| 耐久 (hp) | 声部剩余拆解点数，0–4 | 4 = 完整未损，0 = 已拆解 |
| 拆解 | `hp` 归零事件：音轨 gain→0、该类障碍停止生成并全屏碎裂、画面降饱和 | 拆解**不等于**声部永久消失，可被复活 |
| 复活 | MISS 使某声部 `hp` 从 0（或更低）回升 1 点，音轨恢复发声、该类障碍恢复生成 | 复活是否补发历史障碍：**不补**（见 REQ-DIS-05） |
| PERFECT/GOOD/MISS | 三档判定，窗口见 §7.1 | 时间差 `deltaMs = \|inputT - obstacleT + latencyOffset\| × 1000` |
| 空拍 | 按键时不存在任何落在 GOOD 窗口内的未判定障碍 | 空拍无惩罚，但计入调试日志（试玩分析用） |
| 核心节点 | 声部上被指定为「可涨拆解进度」的障碍（贝斯平台落点、合成器弹幕核心） | 只有核心节点的 PERFECT 才扣 `hp`（见 §7.2） |
| 寂静段落 | 全声部拆解后的 8–16 拍，仅节拍器 | 段内判定对象 = 节拍器光点 |
| latencyOffset | 玩家输入相对音频时钟的系统性偏移（ms），校准得到，可为负 | **只在判定处使用**，禁止用它去平移音频调度 |
| 双时钟 | 权威时钟 = `AudioContext.currentTime`；渲染时钟 = `requestAnimationFrame` 时间戳，仅插值 | 任何「两个时钟换算」的中间量必须是纯函数 |

## 4. 系统总览与模块职责

```
                      ┌──────────────────────────────────────────┐
                      │  data/levels/levelN.json                 │
                      │  ├ sections（段落 / 层进入 / 密度）        │
                      │  └ noteEvents（kick/bass/synth 音符事件）  │  ← 唯一真相
                      └───────────────┬──────────────────────────┘
                                      │ 载入时
                 ┌────────────────────┴────────────────────┐
                 ▼                                        ▼
   ┌───────────────────────┐                ┌──────────────────────────┐
   │ MUS TrackMixer        │  拆解/复活事件  │ PGN PatternGenerator     │
   │  3 条音序/音源 + Gain   │◀──────────────▶│  音符事件 → 障碍实例数组    │
   └───────────┬───────────┘                └────────────┬─────────────┘
               │ 发声（提前 120ms 预调度）                  │ ObstacleInstance[]
               ▼                                          ▼
   ┌────────────────────────────────────────────────────────────────┐
   │ CLK BeatClock  权威时钟：now() / beatAt(t) / 段落 / BPM 变速      │
   └───────┬───────────────────────────────┬────────────────────────┘
           │ now()                         │ now()
           ▼                               ▼
   ┌───────────────┐               ┌──────────────────┐
   │ TIM Timeline  │  同一 pxPerBeat │ OBS 上层世界      │
   │ 下层读谱层      │◀─────────────▶│ Spike/Platform/   │
   └───────────────┘   共享时间轴     │ Barrage + Player  │
                                    └────────┬─────────┘
                                             │ 判定输入（keydown → now()）
                                             ▼
                                    ┌──────────────────┐
                                    │ JDG JudgeSystem  │──grade──▶ DIS DisassembleSystem
                                    └──────────────────┘           │ hp / 拆解 / 复活
                                             ▲                     ▼
                                    校准 latencyOffset      事件 → TrackMixer + VIS 演出
```

### 模块职责与边界（禁止越界）

| 模块 | 负责 | 明确不负责 |
|---|---|---|
| BeatClock | 权威时间、拍序换算、BPM 段落表与变速过渡、发声预调度循环、段落回调 | 判定、音频内容本身、任何画面 |
| TrackMixer | 声部发声（程序合成或分轨文件）、gain 渐变、静音/复活、音量 | 节拍时刻计算（向 BeatClock 取）、障碍生成 |
| PatternGenerator | noteEvents → 障碍实例（时刻、类型、车道、核心标记、速度） | 屏幕坐标（由时间轴公式换算）、判定 |
| Player | 自动奔跑、跳跃弧线、冲刺窗口位移、微调站位、落地状态 | 判定结果消费之外的任何逻辑 |
| Obstacle(+3 子类) | 生命周期（预告→活跃→判定窗→结算→离场）、按时间算位置、被判定后表现 | 主动查询输入 |
| Timeline | 下层时间轴绘制、4 拍可见窗口、节拍标记流动、第 5 关假标记 | 任何判定计算 |
| JudgeSystem | 窗口分级、输入队列与「最近未判定障碍」匹配、空拍识别、超时 MISS 结算、校准偏移 | 拆解进度、音频 |
| DisassembleSystem | 每声部 hp、拆解触发、复活选择规则、寂静段落与终点推进 | 音符、音序、画面细节 |
| Hud/Popup/Calibration | 界面与设置 | 判定路径逻辑 |

## 5. 功能需求清单（REQ）

优先级：**M** = Must（不可砍）、**S** = Should（可降级）、**C** = Could（在砍单清单上）。
「验收」列为该 REQ 的最小可证伪判据。

### 5.1 CLK 节拍与音频时钟内核

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| CLK-01 | 提供 `BeatClock.now()` 返回 `AudioContext.currentTime`（秒，浮点），全局唯一时间来源 | M | 代码静态检查：判定/调度路径无 `scene.time` |
| CLK-02 | 拍序换算：`beatAt(t)`、`timeAtBeat(b)`，变速段落用分段积分而非等速乘法 | M | 第 4 关（120→140）第 100 拍的时刻误差 < 1ms |
| CLK-03 | 发声预调度循环：25ms 轮询、提前 120ms 入队，队列按绝对时刻排序 | M | 人工制造 300ms 主线程阻塞（长 GC 模拟）后，音频无跳音、判定不误判 |
| CLK-04 | BPM 段落表 + 变速过渡：变速前 2 拍打提示音，过渡期内节拍刻度线性变化 | M | 第 4 关盲听可预判变速点 |
| CLK-05 | 段落回调：`INTRO/BUILD/PEAK/DISASSEMBLED/SILENCE` 边界派发事件 | M | 日志可见状态迁移，与画面一致 |
| CLK-06 | AudioContext 在用户手势后 resume（标题点击即手势），并暴露 `ready` 状态 | M | 无手势自动进入时不报错、无静音假死 |
| CLK-07 | 漂移自检：debug 面板实时显示 `|渲染时钟外推 - 权威时钟|` 与音频调度超前量 | S | 5 分钟运行漂移 ≤ 2ms 的截图留档 |

### 5.2 JDG 输入与判定

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| JDG-01 | J/Space = 跳，K = 冲，←/→ = 微调 ±0.3 拍身位，R = 重开，Esc = 暂停，[ / ] = 校准微调 | M | 每键单独触发预期动作；空格不滚动页面（`preventDefault`） |
| JDG-02 | 三档窗口 PERFECT ±50ms / GOOD ±100ms ×关卡缩放；缩放后不得小于 ±40/±80ms（下限保护） | M | 单元测试覆盖 6 关缩放，含下限生效用例 |
| JDG-03 | 一次按键只匹配「时间轴上最近的未判定障碍」；判定后障碍锁定结果，不再被其他键改变 | M | 连打两键只吃掉两个障碍，不重复计数 |
| JDG-04 | **规则优先级（本 PRD 新增，解决策划案歧义）**：① 先按窗口匹配 → 命中即判定；② 未命中且处于落地后 80ms 缓冲内 → 标记为对下一拍的预输入（GOOD 起步）；③ 其余视为空拍，仅提示、不惩罚、不入耐久统计 | M | 空拍紧邻障碍时行为可预测；日志能区分 ①②③ |
| JDG-05 | 超时 MISS 由 BeatClock 回调结算（`t > obstacleT + goodWindow` 且未判定），不依赖玩家输入 | M | 全程不按键，障碍依次自动转 MISS 且不卡状态机 |
| JDG-06 | 判定结果携带 `deltaMs`、`obstacleId`、`track`，写入本局事件流（供结算、回放、试玩分析） | M | 导出的 JSON 事件流可复算 Perfect 率 |
| JDG-07 | 判定动作类型校验：Spike/Platform 只接受跳跃、Barrage 只接受冲刺；用错动作按 GOOD 通过但不涨 hp，不计 MISS | M | 对弹幕按 J 不涨拆解进度且不掉血 |
| JDG-08 | 同一拍最多 1 次输入被消费（无多键同拍双计），同拍障碍上限 1 | M | 两键同拍只判定一次 |
| JDG-09 | 校准小游戏：8 拍跟拍敲击，取中位数（非均值，抗离群）写入 localStorage；提供手动 ±1ms 微调与「重置为 0」 | S | 校准 0ms 与人为 +60ms 两次结果，Perfect 率差 < 3% |

### 5.3 PLR 角色

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| PLR-01 | 自动奔跑，速度 = 时间轴滚动速率（见 VIS-05），不可停止 | M | 上层与下层同速（视觉验证） |
| PLR-02 | 跳跃为**固定高度**抛物线（附录 B 决策 1）：单段、不可二段、空中不可变高；滞空时长 = 拍长 × 系数（§7.5） | M | 从起跳到落地的时间完全可预测，谱面可据此排布 |
| PLR-03 | 冲刺为水平位移（前冲 + 无敌穿弹幕），持续 ≤ 0.35 拍，K 独立键（附录 B 决策 3） | M | 冲刺不会误触发跳跃，反之亦然 |
| PLR-04 | ←/→ 微调只改相位（±0.3 拍身位偏移的视觉/命中补偿），自动回中；**第 1 关不使用**（教学关后解锁） | S | 微调不改变判定时刻本身，只改变站位表现与容差 |
| PLR-05 | 受击：0.5s 无敌帧 + 镜头震动，不中断奔跑、不清空场景 | M | 连续 MISS 不产生「停住」感 |
| PLR-06 | 落地后 80ms 输入缓冲（与 JDG-04 同一实现，禁止两处各写一套） | M | 见 JDG-04 |

### 5.4 OBS 障碍与声部实体

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| OBS-01 | 三类障碍：Spike（红/鼓/踩桩跳）、Platform（黄/贝斯/落点跳）、Barrage（品红/合成器/冲刺穿网） | M | 三色与三动作一一固定 |
| OBS-02 | 障碍 x 位置为时间纯函数：`x = judgeX + (obstacleT - now) × pxPerSec`；**禁止速度积分** | M | 掉帧 5s 后障碍仍在正确拍位（debug 面板比对） |
| OBS-03 | 预告窗口：障碍从进入屏幕到到达判定线 = 4 拍（与下层时间轴可见窗口一致） | M | 4 拍对应像素 == 上下层入场到判定线像素 |
| OBS-04 | 音高→平台高度 3 档（低/中/高），时值→弹幕速度；映射表在配置内可调 | M | 改配置后重载入即生效，无需改代码 |
| OBS-05 | 核心节点标记：Platform 的落点、Barrage 的弹幕核心必须在视觉上可辨识（描边/高亮），非核心同类障碍不给 hp | M | 玩家能在不暂停时说出「哪个是要打的」 |
| OBS-06 | 密度约束校验（载入时硬校验并告警）：任意 4 拍内同类 ≤ 3；每 8 拍至少 1 拍喘息 | M | 自检脚本对 6 份配置全部通过 |
| OBS-07 | 声部拆解时该类在场障碍全屏碎裂并停止生成；复活后从**当前拍之后**恢复生成 | M | 见 DIS-04/05 |
| OBS-08 | 禁止引入第四种声部色；系统色仅青 `#00f0ff` 与白 | M | 视觉走查 |

### 5.5 DIS 拆解与段落系统

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| DIS-01 | 每声部 hp = 4（第 1 关 kick、未配置声部 hp=0 且不参与） | M | 配置缺省即 0 |
| DIS-02 | 核心节点 PERFECT → hp−1；GOOD → hp 不变但连击 +1；MISS → 复活 1 点 | M | 状态矩阵单测（见 §13 用例 T3） |
| DIS-03 | **复活选择规则（补全策划案缺口）**：取「损失点数最多」的声部（hp 最小且 ≥0）；并列时优先级 kick > bass > synth；全部声部 hp=4 时 MISS 仅清连击 + 无敌帧，不改音频 | M | 单测覆盖并列/全满/仅一个已拆解三种局面 |
| DIS-04 | 拆解演出：该类障碍碎裂 + 该轨 gain 0.1s 线性淡出 + 屏幕降饱和 0.3s 恢复 + 大字标题（如「鼓 · 已拆解」） | M | 三者同帧触发，慢放截图可证 |
| DIS-05 | 复活演出：该轨 gain 0.15s 淡入恢复发声，该类障碍自当前拍后恢复，**不补发历史障碍**，hp 回到 1（不是 4） | M | 复活后需再打 3 次核心才拆解，且分母不变（§7.3） |
| DIS-06 | 全声部 hp=0 → 进入 `DISASSEMBLED`，随后 `SILENCE` 段落（8–16 拍，仅节拍器光点，逐拍踩灭） | M | 寂静段内无可判定的声部障碍 |

## 7. 数值与参数规格

### 7.1 判定参数

| 参数 | 基准 | 关卡缩放 | 实际范围 | 备注 |
|---|---|---|---|---|
| PERFECT 窗口 | ±50ms | ×1.2 / ×1.1 / ×1.0 / ×1.0 / ×0.95 / ×0.9 | ±45 → ±60ms | 缩放下限 ±40ms（JDG-02） |
| GOOD 窗口 | ±100ms | 同上 | ±90 → ±120ms | 下限 ±80ms |
| 落地预输入缓冲 | 80ms | 常量 | — | 仅对下一拍生效一次 |
| 无敌帧 | 0.5s | 常量 | — | 不冻结奔跑 |
| 微调身位 | ±0.3 拍 | 常量 | — | 教学后解锁，仅表现/容差 |

> **重要提醒（§12 P0-3）**：浏览器音频输出延迟常见 20–120ms（蓝牙设备可达 200ms+），而 ±50ms 的 PERFECT 窗口在 132BPM 下只占拍长的 11%。建议基准改为 **±60 / ±110ms**，把收紧到 ±50 的动作留给设置里的「严格模式」，并在 README 说明。默认宽一档不会破坏设计意图（拆解仍需 4 次 PERFECT），但默认紧一档会直接毁掉 D7 试玩。

### 7.2 声部耐久与状态矩阵

| 事件 | 连击 | hp（该声部） | 音轨 | 障碍生成 | 画面 |
|---|---|---|---|---|---|
| 核心 PERFECT | +1 | −1 | 不变 | 继续 | 粒子 + 顿帧 + 金闪 |
| 非核心 PERFECT | +1 | 不变 | 不变 | 继续 | 粒子 |
| GOOD（核心或非核心） | +1 | 不变 | 不变 | 继续 | 轻提示 |
| MISS（声部未全满） | 0 | **其他**损失最大声部 +1（≤4） | 复活淡入 | 恢复（当前拍后） | 红闪 + 震动 |
| MISS（全声部 hp=4） | 0 | 不变 | 不变 | 不变 | 红闪 + 震动 |
| hp 归 0 | — | 拆解态 | gain→0（0.1s） | 停止 + 在场碎裂 | 降饱和 + 大字 |
| 寂静段光点 MISS | 0 | 不变 | 不变 | — | 光点重亮一拍 |

### 7.3 结算统计口径

```
总障碍数 N      = 本关 noteEvents 生成的「可判定障碍」总数（固定分母，与复活/重开无关）
核心节点数 M    = 其中标为核心节点的数量（≥ 12，三声部各 4）
PERFECT 数 P    = 判定为 PERFECT 的障碍数（含非核心）
核心 PERFECT 数 = 涨 hp 的次数（拆解用）
Perfect率       = P / N            ← 策划案口径；建议同时显示「核心命中率 = 核心PERFECT / M」
S = Perfect率 ≥ 0.85 且 MISS == 0
A = Perfect率 ≥ 0.70
B = Perfect率 ≥ 0.50
C = 通关即保底
```

未通关（寂静段未走完就退出/关闭）不写档。中途重开（R）不污染上一局的存档，只覆盖当前局事件流。

### 7.4 关卡难度参数（继承策划案 §7，补齐时间）

| 关 | BPM | 密度（个/4拍） | 窗口缩放 | 时长估算 | 4 拍预告换算 |
|---|---|---|---|---|---|
| 1 | 110 | 1.0 | ×1.2 | 128 拍 ≈ 69.8s | 2.18s |
| 2 | 120 | 1.5 | ×1.1 | 128 拍 ≈ 64.0s | 2.00s |
| 3 | 126 | 2.0 | ×1.0 | 128 拍 ≈ 61.0s | 1.90s |
| 4 | 120→140 | 2.5 | ×1.0 | 160 拍 ≈ 71.4s | 2.00→1.71s |
| 5 | 128 | 2.0 | ×0.95 | 144 拍 ≈ 67.5s | 1.88s |
| 6 | 132 | 3.0 | ×0.9 | 160 拍 ≈ 72.7s | 1.82s |

> 密度 × 窗口同时收紧，第 6 关相对第 1 关是 **3 倍障碍量 + 最紧窗口 + 最短预告**，跨度陡峭。建议把第 6 关窗口缩放从 ×0.9 抬到 ×0.95（即与第 5 关持平），把难度主要由密度而非窗口表达——D7 试玩数据出来后定。

| HUD 带高 | 0.08 × H | 策划案 |
| 时间轴带高 | 0.32 × H，标记高 40px | 策划案 |

**约束自检（必须能算）**：同类障碍 4 拍 ≤ 3 个 → 相邻同类障碍最小间隔 ≥ 1.33 拍；滞空 0.9 拍 + 落地缓冲 80ms（≈0.18 拍）= 1.08 拍，**小于 1.33 拍**，因此不存在「落地前遇到下一个同类」的硬冲突。但第 6 关混合三类障碍时可能出现「跳完立刻要冲」，需靠 JDG-06 的输入缓冲兜底，并在谱面自检里加一条规则：**同一拍不得同时出现两类障碍**。

## 11. 关卡详规 L1–L6

统一：`introBeats = 4`（安全区），`silenceBeats = 12`（除第 1 关 8）。

**L1 启动 · 极简电子 · 110BPM · 128 拍 · 仅鼓 · 窗口 ×1.2 · 密度 1.0**
机制：读谱 + 节拍跳跃。kick 只在 4/4 的正拍，前 16 拍仅每 2 拍一根桩，第 16 拍后按「4 拍内 ≤ 3」常规密度。核心节点 = 前 4 个正拍桩（保证 4 次 PERFECT 可达成拆解）。音色：kick + 轻微 hi-hat 铺底（铺底不参与拆解）。教学浮层内嵌。验收：首次玩家 20 拍内出现首个 PERFECT。

**L2 脉冲 · Synthwave · 120BPM · 128 拍 · 鼓+贝斯 · ×1.1 · 1.5**
机制：贝斯平台。段落：0–16 仅鼓 → 16–96 鼓+贝斯 → 96–120 高密度 → 120–128 收束。音高→平台高度 3 档，核心节点 = 每 8 小节第一拍的平台落点。验收：玩家能说出「黄色是要落上去的」。

**L3 弹幕 · Chiptune · 126BPM · 128 拍 · 三声部 · ×1.0 · 2.0**
机制：冲刺 + 合成器琶音弹幕。弹幕**只出现在冲刺拍**（R3 缓解硬约束），琶音时值→弹幕速度。验收：三声部同屏时仍能分辨核心节点；不看时间轴可通关。

**L4 过载 · Drum&Bass · 120→140 · 160 拍 · 三声部 · ×1.0 · 2.5**
机制：段落变速。第 64 拍变速，前 2 拍过渡提示音 + 画面提示（色带扫过）。TIM-02 保证时间轴按拍等距。验收：变速瞬间无「跳拍」感，判定不失准。

**L5 干扰 · Glitch · 128BPM · 144 拍 · 三声部 · ×0.95 · 2.0**
机制：假节拍（视觉说谎）+ 故障美学。全关最多 8 处假标记（`ghostBeats`），每处持续 1–2 拍并伴随故障闪烁提示「信号干扰」。假标记**只在时间轴层**，且绝不落在核心节点拍上（避免把机制变成随机惩罚）。验收：纯听觉通关 0 次 MISS。降级预案：砍单第 2 项时，本关只保留 2 处演出型假标记 + 视觉故障，不做机制关。

**L6 终曲 · 完整编曲 · 132BPM · 160 拍 · 三声部高密度 · ×0.9（建议 ×0.95）· 3.0**
机制：**拆解顺序自选**。三声部核心节点同时在场、始终可交互（DIS-10）；`freeOrder: true` 时不预设拆解顺序，段落仍按配置进入。谱面上保证任意单声部在关内至少出现 6 个核心节点（给玩家容错）。建议窗口回抬 ×0.95（§7.4）。验收：三种首选顺序都能通关；结算回放顺序与玩家实际一致。

## 12. 方案审阅结论：问题与待决策清单

以下是我在通读策划案后发现的**具体缺口与风险**，按严重度排列。P0 不解决会在中后期返工。

### P0（开工前必须拍板）

**P0-1 Safari 不支持 Ogg Vorbis，方案 A/B 的 `.ogg` 分轨会在 Safari 全线静音。**
策划案 §8 把「分层 BGM：每关 3–4 条 OGG 分轨」写成默认路径，§13 R5 只把 Safari 问题列为「低概率·中影响」。实际是确定的格式不支持。
处置：**坚持方案 C（程序合成）**，把 §15 里 MUS-06 作为「若将来升级 loop 才需要」的预案，并给 D3 决策加上「不做 A/B 的音频文件依赖」这一条硬约束。收益：同时消掉 R5 和 R2 的一半。

**P0-2 缺物理与画面参数表，「固定跳跃高度」不可实现。**
没有滞空时长、跳跃峰值高度、平台三档高度、世界滚动速率，L2 的贝斯平台与 L1 的尖刺间隔无法验证是否可达，D4 会返工。
处置：冻结 §7.5 全表（D1 内出，玩法工程师负责）。关键决策：**跳跃滞空时长定义为拍长的 0.9 倍而非固定秒数**，否则第 4 关变速会让所有跳跃「跳过头」。

**P0-3 判定窗口对浏览器输出延迟过于激进（±50ms）。**
处置：基准改 ±60/±110，另提供 `strictWindow` 开关；D7 用试玩者的 `deltaMs` 分布反推终值（JDG-06 的事件流正是为此）。

**P0-4 noteEvents 同时驱动发声与障碍，谁是格式的拥有者？**
这是本项目最大的架构优点，也是最大的分工耦合点：音频工程师与关卡工程师会同时想改这份数据。
处置：schema 由玩法工程师在 D1 定（§8.1 为提案稿），D1 EOD 冻结；内容侧只增数据不改字段；字段扩展走变更流程。

**P0-5 复活 / 寂静段 / 分母 三处规则缺口。**
「受损最多的声部」在并列与全满时未定义；`DISASSEMBLED → SILENCE` 段内 MISS 是否复活未定义（策划案状态机的回退箭头在寂静段会形成逻辑空洞）；Perfect 率分母在复活后是否重算未定义。
处置：DIS-03、DIS-05、DIS-07、§7.3 已给出补全，需制作人确认口径。

### P1（开发中期会踩，需提前规避）

**P1-1 itch.io iframe 下 localStorage 分区/可被清理，进度体验受损。**
同一游戏在 Vercel 与 itch.io 的存档不互通；itch 用户清缓存即丢档。
处置：SAV-04 导出/导入码（低成本，1 小时级）+ itch 页面文案说明。

**P1-2 上下层滚动速率必须同源，否则「对齐虚线」与双读谱承诺崩掉。**
策划案给了下层 pxPerBeat 语义但没规定上层世界速率。
处置：VIS-05 定为同值且角色 x = 判定线 x。

**P1-3 输入规则优先级未定义（空拍 vs 落地预输入）。**
处置：JDG-04。

**P1-4 回放演出（0.5 天估算）风险被低估。**
「整首歌按拆解顺序重新组装」要求音频能在任意时刻分层启动，并同步渲染操作剪影；Phaser 场景里做这件事在 D8 一天内很紧。
处置：降级为 **2× 加速的分轨叠加重组**（不做角色剪影，或用简单剪影），并把 UI-07 作为砍单第 1 项的明确对象。若保留，估算上调至 0.75 人日。

**P1-5 颜色即信息 = 色盲不可玩。**
红 / 黄 / 品红三色对常见色盲（Deuteranopia/Protanopia）区分度很差，而策划案明令「禁止引入第四种声部色」。
处置：不违反色彩约束的前提下，用**形状 + 位置通道**做冗余编码（尖刺=三角、平台=横条、弹幕=六边形，TIM-01），并加 `reduceFlash` 开关。这是作品集里可写进 README 的加分项。

**P1-6 每关一个分支 + D7 起只 cherry-pick bugfix** 对 1–2 人团队偏重。
处置：改为单 main + tag（`d5-content-complete` 等），或只给「关卡配置」开分支、代码不开分支（见分工文档第 7 节）。

**P1-7 暂停时挂起 `AudioContext` 会造成恢复瞬间的时间基准跳变。**
`currentTime` 在 suspend 期间仍推进（实现相关），恢复后需重新对齐段落，否则暂停前后判定错位。
处置：CLK 提供 `pause()/resume()`，内部重算 `timeOrigin` 而非重置拍序；UI-05 验收补一条「暂停 30s 后恢复无错位」。

### P2（建议，不影响开工）

- 建议给每关加一个「拆解回顾」小图（三声部 hp 随拍变化），数据已在事件流里，成本极低，作品集叙事很强。
- 建议在结算加「核心命中率」，因为 Perfect 率含非核心 PERFECT，会让 L1（只有鼓）与 L6（三声部）不可比。
- 教学浮层建议加一条「可跳过」，第 2 次进第 1 关的人不需要再看。
- `R` 重开务必走「场景重建 + 统一 teardown 检查」（PERF-08），历史经验里 80% 的重开 bug 来自残留的 25ms 调度 interval。

## 15. 附录

### 15.1 砍单优先级（策划案原序 + 本 PRD 建议调整）

原序：1 结算回放 → 2 第 5 关假节拍 → 3 延迟校准小游戏 → 4 第 6 关自由顺序 → 5 选关徽章动画。
**建议调整**：把「3 校准小游戏」提到第 1 位砍（保留 `[` `]` 微调即可满足 P0-3 的兜底），因为校准小游戏会**直接改善试玩手感数据**，而回放只在最后一眼加分。第 2 位砍回放（降级为 2× 分轨重组）。第 3 位假节拍降级为演出。
**不可砍**：判定手感、拆解演出、6 关数量、教学浮层（第 1 关引导是支柱 2 的兑现）、形状冗余编码（成本 < 0.25 人日）。

### 15.2 动效 checklist（D7/D8 逐项核对）

- [ ] 全屏边缘随节拍脉冲（当前声部色）
